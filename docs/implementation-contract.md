Read docs/roadmap.md; all 11 accepted deliverables ship. Shared types are in shared/types.ts (parent owns that file). Optional additions keep old records working. ## Foundation API and exports (parent implements)
- shared/domain.ts: existing exports retained; nextRenewal(sub, asOf=today()): string|null; isCurrent(sub, asOf=today()): boolean; decidingEvidence(sub): Evidence|undefined; verdict(sub): Verdict; offerIsFresh(offer): boolean. recommendations respects fresh offers/check-ins/dismissals. monthly is arithmetic only (filter isCurrent first). billingInMonth excludes on/after endDate. Terms/PlanOffer/Research/Evidence fields in shared/types.ts.
- shared/lifecycle.ts: migrateWorkspace(data, asOf?): boolean (in-place), recordOutcome(workspace, subscriptionId, input, source='manual'): RecordedOutcome. input={kind:'cancel'|'plan',effectiveDate,plan?,price?,cycle?,nextBilling?,note?}; scheduled change until effective date, immediate when date today. termsOf(sub), subscriptionFingerprint(sub).
- GET /api/workspace -> Workspace. POST /api/workspace/visit -> {previousVisitAt?: string, workspace: Workspace}; use once on initial app load, not polling. POST /api/subscriptions/:id/keep -> {renewal:string}; stores keptRenewals[id] for nextRenewal.
- Existing subscription PATCH accepts hasDataToMove boolean and status management via outcome route, not arbitrary status.
- POST /api/subscriptions/:id/evidence -> accepts source='Self-reported' (default), summary, observedAt, metric, unit, usage optional, limit optional, days. Server assigns confidence. DELETE /api/subscriptions/:id/evidence/:evidenceId. POST /api/subscriptions/:id/check-in -> {wouldRenew:boolean,value:'personal'|'shared'|'background',summary?:string}; creates Check-in evidence, no fabricated usage.
- Inspection start/capture routes retained. capture returns evidence draft with draftId. save requires {draftId, summary,usage,limit,days,metric?,unit?}; validates server draft/session then saves exact user-edited values. GET /api/subscriptions/:id/inspect returns {liveViewUrl?,draft?,draftId?} to restore open UI across reload. POST /api/inspect/close invalidates draft.
- POST /api/subscriptions/:id/outcomes -> recordOutcome input above; server uses source manual. Requires {attested:true}. Returns Workspace. Demo apply handled only by action router. Outcomes include separate manual/demo monthlyReduction; UI labels user-recorded reductions (projected until effectiveDate).
- GET /api/workspace/export -> versioned {format:'folio',version:2,workspace:Workspace}, stripped secrets/browser data; actions historical. POST /api/workspace/import -> {backup,confirmReplace:true} returns Workspace, strict validated non-running restore.
- POST /api/workspace/recovery -> {code:string}; shows once, replaces previous hashed token. POST /api/workspace/restore -> {code:string,confirmReplace:true}, sets workspace cookie; returns Workspace. DELETE /api/workspace -> {confirm:true}, cleans workspace and cookie; running writes block.
- POST /api/workspace/calendar -> {url:string}; rotates hashed random token. DELETE /api/workspace/calendar revokes. GET /api/calendar/:token.ics returns sanitized no-store ICS. Backup excludes tokens. UI warns link/code are private and offers copy/download without saving plaintext in localStorage.

## Discovery API (agent implements in server/discovery.ts exporting default Express Router)
Mount router at app root (all paths start /api). Workspace ID res.locals.workspace.
- POST /api/import/inspect {text} -> {headers:string[],sample:Record<string,string>[],mapping:{merchant?,amount?,date?,currency?,debit?,credit?,cycle?,domain?,category?,plan?}}.
- POST /api/import/parse {type:'csv'|'email',text?,files?:{name:string,text:string}[],mapping?,dateOrder?:'MDY'|'DMY'|'YMD',chargeSign?:'positive'|'negative'} -> {candidates:ImportCandidate[],report:ImportReport}; candidate extends Subscription with import metadata {confidence:'likely'|'possible',reason,selected,matchId?,requiresReview?:string[],sourceExcerpt?,inferredFields?}; final agreed type in shared/discovery.ts. Keep old candidates-only clients working.
- POST /api/import/confirm {subscriptions:ImportCandidate[],source:'CSV'|'Email',matches?:Record<candidateId,existingId>} -> {count,merged,skipped}; selected candidates only sent by UI. Guard explicit merge/matched existing; structured charge dedup. No silent synthetic status changes.
- POST /api/subscriptions/:id/research -> Research; save on subscription; structured plans must have literal supporting quote and amount. Quote/URL validation, schema validation, errors no partial writes.
- POST /api/subscriptions/:id/offers {kind,plan,price,cycle,capabilityLoss,migrationEffort?,sourceUrl?,quote?,offerId?} -> PlanOffer; user explicitly confirms terms, server sets provenance/confirmedAt. Existing offerId confirms previously extracted offer without client upgrading arbitrary provenance. HasDataToMove declaration governs migration.
- POST /api/confirmation/parse {text} -> {endDate:string|null,summary:string}; editable suggestion, no write. Dates unverified inferred flagged in summary.

## Actions API (agent implements in server/actions.ts exporting default Express Router)
Mount at root. Preserve POST /api/actions/prepare {subscriptionId,kind,offerId?,effectiveDate?,variant?:'standard'|'alternate'} -> Action. No fresh confirmed personal offer -> clear 409 except cancel. Demo lower price targets must be cheaper; annual disallowed on annual. Migration requires source Demo fixture with documents OR hasDataToMove=true. End-of-period default cancel/downgrade; migration/annual date explicitly approved.
- POST /api/actions/:id/approve -> 202. Concurrency/proposal expiry/stale fingerprint guard. waitUntil lives here. POST /api/actions/:id/discard -> Action. POST /api/actions/:id/reprepare -> Action (fresh approval required). GET /api/actions/:id -> Action.
- POST /api/actions/:id/apply -> Workspace; only completed verified Demo workspace + Demo-source subscription; idempotent; call shared/lifecycle.recordOutcome(...,'demo') and supersede obsolete proposals. If effective date future, changes schedule correctly rather than pretending immediate.
- GET /api/actions/:id/artifact -> screenshot only after workspace ownership check.
- Hosted controlled merchant HTML/API routes under /api/merchant/* (public capability-token protected; no Folio workspace mutation rights). State in Neon-backed server sessions or own table (cleanupWorkspace export). Per-run token stays server-side/action session; never in workspace action. Browser navigates hosted URL, all writes only via visible UI flow. Verification server reads independent merchant state and requires flow-complete receipt + approved terms including effectiveDate. Both variants supported, different labels and decoy. Test spec eight live runs later with root's hosted deployment. No local Playwright substitute for user UI; Kernel is product integration and authorized for controlled tests.
